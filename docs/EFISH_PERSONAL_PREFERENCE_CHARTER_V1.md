# Efish Personal Preference Charter V1

Status: `owner_review_required`
Owner review completed: `false`

This public-safe charter defines the review surface for
`efish-personal-judge-v1`. It does not contain approved owner preferences yet.
Every candidate value remains unset until the owner explicitly reviews and
exports a profile. Codex must not infer missing values from project history,
private conversations, or perceived personality.

## Authority boundary

DeepSeek remains responsible for factual content, reasoning, knowledge, logic,
philosophy, and the final answer's semantics. The local judge may classify only
personal fit, voice issues, presentation mode, and whether personalization is
confident enough to apply. Presentation may affect non-semantic UI behaviour;
it may not edit, reorder, hide, or append answer text.

The judge must not invent facts, alter conclusions, diagnose an end user's
emotion, infer sensitive identity, make medical/legal/financial decisions, or
claim authorship of text generated by DeepSeek.

## Owner preference axes

These are proposed schema choices, not statements about the owner's actual
preferences.

| Axis | Allowed values | Owner-selected value |
| --- | --- | --- |
| `response_density` | `sparse`, `compact`, `moderate` | unset |
| `warmth` | `restrained`, `quiet_warm`, `expressive` | unset |
| `directness` | `direct`, `balanced`, `exploratory` | unset |
| `formality` | `casual`, `neutral`, `formal` | unset |
| `reflection` | `practical`, `mixed`, `reflective` | unset |
| `explanation_depth` | `minimal`, `bounded`, `detailed` | unset |
| `assistantness_tolerance` | `very_low`, `low`, `moderate` | unset |
| `question_frequency` | `rarely`, `only_if_needed`, `conversational` | unset |
| `humour` | `none`, `light`, `playful` | unset |
| `philosophy_style` | `concise_open`, `dialectical`, `analytic` | unset |

The editable candidate template is
`data/personal_judge/efish_personal_style_profile_v1.template.json`. Its null
values are deliberate. A profile becomes authoritative only when every axis is
selected, `status` is `owner_approved`, `owner_review_completed` is `true`, and
an explicit owner review export exists. The schema enforces complete values for
that approved state.

## Judge head contract

The four V1 heads use only these outputs:

- Personal Fit: `PERSONAL_FIT`, `NEUTRAL`, `PERSONAL_MISMATCH`.
- Voice Issue Multi-label: `too_formal`, `too_verbose`,
  `too_assistant_like`, `too_cold`, `too_warm`, `too_explanatory`,
  `too_structured`, `too_generic`, `too_apologetic`, `too_enthusiastic`,
  `unnecessary_question`, `unnecessary_disclaimer`, `repetitive`,
  `textbook_tone`.
- Presentation Mode: `compact`, `quiet`, `reflective`, `direct`,
  `playful_light`, `neutral`.
- Confidence / Abstention: `CONFIDENT_PERSONALIZE`,
  `DEFAULT_PRESENTATION`, `OUT_OF_SCOPE`.

No factuality, truth-probability, logic-correctness, emotion, personality, or
natural-language generation head is part of this charter.

## Personal is not end-user profiling

“Personal” means that the judge applies an explicitly owner-approved efish
brand preference. It does not mean constructing a psychological profile of an
end user. The profile must never store or infer health or diagnosis, religion,
politics, sexuality, criminal history, private diary/chat content, passwords,
identifiers, API keys, or other sensitive traits.

Any later end-user adaptation is limited to explicit structured settings such
as preferred language or response density and separately approved session
state. There is no automatic learning from live conversations, background
online learning, hidden behavioural profiling, or raw private source intake.

## Dataset boundary

`schemas/efish_personal_judge_example_v1.schema.json` permits only public-safe
classification records and project-approved source categories. A pair may be
included to supervise an owner preference contrast, but pairwise selection is
not the product architecture. An example cannot be marked training-eligible
unless its owner review status is `OWNER_APPROVED`.

The schema is necessary but not sufficient for content safety: a separate
provenance and public-safety audit must inspect text before any future training.
This J0 charter contains no dataset examples, private profile, owner labels, or
training authorization.
